# PMC2 候选查询事务层

代码位于 src/FanControl.Core/Pmc2QueryReader.cs。现有开发版诊断适配器已发送受限D5查询，取得一组与EC反馈吻合的双路RPM；尚未接入WPF，连续采样未通过。它是后续控制验证所需的协议实现，不能作为调速完成证据。

事务顺序为 D5/12 标志查询、D5/18 第一通道两字节转速、D5/19 第二通道两字节转速、D5/12 标志复核。每次请求先等待输入缓冲可用；不消费旧的输出。响应按固件候选的低字节在前解码，零是合法反馈，大于 7500 拒绝。标志变化、额外输出、短响应和错误都失败，而不是返回成功样本。

每轮持有适配器的独占事务 lease。开发版诊断适配器负责 21CX/HYCN42WW、5571/1060=00、PMC2 启用和 68/6C 基址验证、总线互斥和本机 I/O 调用的时间限制。身份与配置检查在DeveloperQueryTransport内执行。协议层只有单调时钟截止和轮询次数上限，不能打断阻塞的原生 I/O。中途取消或失败后停止该 reader，不自动重试可能留下响应的事务。

这层实际只发送候选查询 D5 参数 12/18/19；查询仍需要向命令/数据端口写入请求，但不包含 C7、D7、D5/10、D5/11 或风扇目标设置。

主代理运行 tests/Pmc2ProtocolVerification：269 项检查、62 个 I/O 边界故障注入通过。覆盖字节顺序、零转速、超范围、忙状态、旧 FIFO、短响应、额外字节、标志改变、迟到返回、取消和失败后禁止继续访问。模拟检查本身不运行硬件；另有实机结果见PMC2_RUNTIME_RESULTS.md。既有曲线计算检查另行通过；它仍未连接执行器。

剩余关键步骤：提供受支持的签名传输，运行候选查询与现有 EC 反馈交叉核对；确定完整恢复状态；随后验证两路设置、失效恢复和实际自动曲线执行。

实机传输位于src/EcPmcConfigProbe/DeveloperQueryTransport.cs；自定义模块Pmc2Query.p在内核限制端口和D5/12、18、19值。当前100ms截止包含身份检查、模块加载和最终恢复；发生过超时，后续检测到待取输出而停止，没有排空FIFO或盲目重发。长时间稳定性尚未验收。

2026-10-02离线修订：超时异常现在报告具体完成阶段、耗时和上限，区分事务建立、命令/参数写入、各响应状态/数据读取、最终状态和清理。保持原100ms默认值，没有移除身份、配置或恢复计时。新增延迟建立、命令、参数、数据、清理用例；主代理实际运行284项检查通过（原62个I/O故障边界仍覆盖），已重新发布诊断程序。原生调用依旧同步：截止是返回后的验收条件，不能宣称能中断驱动调用或保证100ms返回。

计时进一步修正：实测Sleep(1)在本机CLI进程平均约13.5ms，短期timeBeginPeriod(1)请求期间约1.9ms。新增PollTimerResolution在诊断期间请求并在finally匹配释放；无管理员、无硬件的实际对照返回TimerEndResult=0。没有把截止放宽，也不保证OS调度或原生I/O可中断，实机连续查询仍待下一轮。
